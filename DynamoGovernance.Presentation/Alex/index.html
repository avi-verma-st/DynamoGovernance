03Bounded queueUp to 1,024 records; event producers never block Dynamo.
04Daily JSONLBackground writer appends records to the user's local application data.

Best effort by design

Telemetry failures are isolated from the host. A full queue or write failure can drop records; shutdown allows a short, 200 ms drain window.

Log location
%LOCALAPPDATA%\DynamoGovernance\Logs\telemetry_yyyy-MM-dd.jsonl

The current envelope does not include a schema version or event ID.

03 / Data boundariesMetadata, not design content

What the prototype can tell us

Operational signals.
Not the design itself.

Captured today

  • Session and host / Dynamo / extension versions
  • Graph opened, saved and closed
  • Graph name, ID, path when available and file size
  • Node count and graph-scoped package metadata
  • Evaluation start/end correlation and success

Explicitly not captured

  • Node input/output values or component-level identities
  • Geometry, model content, previews or screenshots
  • Graph file contents or embedded scripts
  • Exception text, stack traces or failing inputs
  • Machine-wide inventory of installed packages
Current logs contain raw Windows user + machine IDsGraph paths and names may be sensitive

Local storage is not the same as anonymous: session IDs link activity to the session-start identity record.

04 / Governance gateResolve before production or centralization

The next work is partly technical, partly policy

Agree the rules
before widening collection.

01

Identity

Approve raw identifiers, pseudonymize them, or remove them. Decide whether user-level reporting is necessary.

02

Document metadata

Choose whether paths and names are retained, minimized, tokenized, or excluded.

03

Dependencies

Set the minimum useful package fields; internal names and repository URLs can reveal organizational details.

04

Lifecycle controls

Set retention, local file access, deletion, user notice and audit expectations.

05

Central service

Only consider transport after access, encryption, region, incident response and ownership are agreed.

06

Shared contract

Approve event names, schema versioning and cross-tool compatibility before adding another source.

Risk review material is prepared; collection decisions remain open in project documentation.

05 / Future routesSequence is a proposal, not a commitment

Three routes, ordered by dependency

Make the local path
trustworthy first.

Route A · Foundation

Harden the prototype

Decide field minimization, surface dropped-record diagnostics, define retention and access expectations, and add an explicit schema version before contract expansion.

Gate: Security / Privacy / Risk field approval

Route B · Broaden tools

Validate Grasshopper

Map document lifecycle and dependency metadata against the Rhino API. Prove what is technically available and safe before implementing a second collector.

Gate: shared schema + API feasibility

Route C · Central insight

Evaluate secure transport

Design an opt-in or governed ingestion path, role-based reporting, encryption, region, retention and deletion controls, while preserving local-only use as an independent option.

Gate: separate architecture and risk approval
