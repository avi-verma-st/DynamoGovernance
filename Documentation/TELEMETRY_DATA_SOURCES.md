# Telemetry Data Sources and Collection Timing

This document explains where Dynamo Governance obtains telemetry data and when each value is collected.

## Collection flow

1. Dynamo loads the extension.
2. The extension collects identity and application information.
3. When Dynamo is ready, the extension subscribes to workspace events.
4. Node and graph activity is captured as it occurs.
5. Common event information is added to each record.
6. Records are written to a local JSONL file by a background worker.

## Extension startup

**When:** Dynamo calls `GovernanceTelemetryExtension.Startup()`.

**Code:** `DynamoGovernance.Extension/GovernanceTelemetryExtension.cs`

| Data | Source |
|---|---|
| User ID | `Environment.UserDomainName` and `Environment.UserName`, read by `IdentityService.GetUserId()` |
| Machine ID | `Environment.MachineName`, read by `IdentityService.GetMachineId()` |
| Host name | Current process name from `Process.GetCurrentProcess()` |
| Host version | Product version of the current process executable |
| Dynamo version | `StartupParams.DynamoVersion`, supplied by Dynamo |
| Extension version | Version of the `DynamoGovernance.Extension` assembly |
| Session ID | New `Guid` generated by `GovernanceService.StartSession()` |
| Session start time | Current UTC time |
| Session timer | `Stopwatch` started by `GovernanceService.StartSession()` |

The user and machine values are currently stored as plain text for testing.

## Extension ready

**When:** Dynamo calls `GovernanceTelemetryExtension.Ready()`.

**Code:** `DynamoGovernance.Extension/GovernanceTelemetryExtension.cs`

At this stage, the extension:

- Subscribes to existing Dynamo workspaces.
- Watches for workspaces being opened, changed, or removed.
- Subscribes to node addition and removal events.
- Subscribes to graph evaluation events.
- Writes the `extension.ready` event.

## View extension

**When:** Dynamo discovers `DynamoGovernance_ViewExtensionDefinition.xml` and calls `GovernanceViewExtension.Loaded()` after the UI is ready.

**Code:** `DynamoGovernance.ViewExtension/GovernanceViewExtension.cs` and `DynamoGovernance.ViewExtension/GovernanceView.cs`

The view extension adds the `Dynamo Governance` WPF sidebar and opens the Design Automation Hub, Dynamo Training, or Dynamo Development Resources in the user's default browser. Resource navigation does not currently call `GovernanceService`, collect identity or graph data, or write a telemetry event.

## Node added or removed

**When:** Dynamo raises `WorkspaceModel.NodeAdded` or `WorkspaceModel.NodeRemoved`.

**Code:** `GovernanceTelemetryExtension.OnNodeChanged()`

| Data | Source |
|---|---|
| Graph ID | `WorkspaceModel.Guid` |
| Saved state | Whether `WorkspaceModel.FileName` contains a value |
| Run mode | `HomeWorkspaceModel.RunSettings.RunType` |
| Node count | Number of items in `WorkspaceModel.Nodes` |
| Custom-node count | Number of nodes identified as custom-node functions |
| Node ID | `NodeModel.GUID` |
| Node name | `NodeModel.Name` |
| Node type | Full .NET type name returned by `NodeModel.GetType()` |
| Custom-node status | Determined from the node’s runtime type |

## Graph execution started

**When:** Dynamo raises `HomeWorkspaceModel.EvaluationStarted`.

**Code:** `GovernanceTelemetryExtension.OnEvaluationStarted()`

| Data | Source |
|---|---|
| Start time | Current UTC time |
| Execution number | Counter maintained separately for each workspace |
| Graph information | Current `WorkspaceModel` |
| Evaluation requested | Set to `true` |
| Evaluation performed | Initially set to `false` |
| Trigger | Inferred as `automatic_change` or `manual_run` from the run mode |
| Execution timer | New `Stopwatch` started for the graph run |

The graph-start event ID is retained so the completion event can be correlated with it.

## Graph execution completed

**When:** Dynamo raises `HomeWorkspaceModel.EvaluationCompleted`.

**Code:** `GovernanceTelemetryExtension.OnEvaluationCompleted()`

| Data | Source |
|---|---|
| Completion time | Current UTC time |
| Duration | Elapsed time from the graph execution `Stopwatch` |
| Evaluation performed | `EvaluationCompletedEventArgs.EvaluationTookPlace` |
| Evaluation succeeded | `EvaluationCompletedEventArgs.EvaluationSucceeded` |
| Execution status | Calculated from evaluation success and node warnings or errors |
| Node warnings and errors | Current `NodeModel.State` values |
| Evaluation exception | `EvaluationCompletedEventArgs.Error` |
| Warning count | Number of captured warning issues |
| Error count | Number of captured error issues |

Execution status can be `succeeded`, `succeeded_with_warnings`, `failed`, or `skipped`.

To keep records bounded, the logger captures no more than:

- 25 issues
- 1,024 characters per issue message
- 2,048 characters per exception message
- 8,192 characters per stack trace

## Extension errors

**When:** An exception occurs inside a protected extension operation.

**Code:** `GovernanceService.LogExtensionError()`

| Data | Source |
|---|---|
| Operation | Name of the operation that failed |
| Exception type | Full .NET exception type |
| Message | `Exception.Message` |
| Stack trace | `Exception.StackTrace` |
| Result | Set to `failed` |
| Error count | Set to `1` |

Logging errors are isolated and do not interrupt Dynamo graph execution.

## Extension shutdown

**When:** Dynamo calls `GovernanceTelemetryExtension.Shutdown()` or the service is disposed.

**Code:** `GovernanceService.EndSession()`

| Data | Source |
|---|---|
| Shutdown reason | Defaults to `dynamo_shutdown` |
| Shutdown time | Current UTC time |
| Session duration | Elapsed time from the session `Stopwatch` |

## Values added to every event

**When:** Immediately before an event is queued for logging.

**Code:** `GovernanceService.LogEvent()`

| Data | Source |
|---|---|
| Schema version | Fixed as `1.0` |
| Event type | Operation currently being logged |
| Event version | Fixed as `1.0` |
| Event ID | New `Guid` generated for the event |
| Session ID | ID generated at extension startup |
| Sequence number | Incrementing session event counter |
| Correlation ID | Event ID or related graph-start event ID |
| Causation event ID | ID of the event that caused the current event, when available |
| Occurrence time | Event time or current UTC time |
| Identity | Values collected when `GovernanceService` is created |
| Application information | Values collected during extension startup |
| Result | Status and warning/error totals supplied by the event |
| Record creation time | Current UTC time |
| Record creation duration | Time required to construct the telemetry record |
| Producer | Fixed as `DynamoGovernance` |
| Delivery method | Fixed as `local_jsonl` |
| Privacy profile | Currently fixed as `testing_plaintext` |

## Local log writing

**When:** After an event is placed in the telemetry queue.

**Code:** `DynamoGovernance.Core/Services/TelemetryLogger.cs`

A background worker serializes each record and appends it to:

```text
%LocalAppData%\DynamoGovernance\Logs\telemetry_YYYY-MM-DD.jsonl
```

Each line contains one complete JSON event. File I/O is isolated from Dynamo callbacks, queue writes are non-blocking, and records may be dropped when the bounded queue is full rather than delaying graph execution.
